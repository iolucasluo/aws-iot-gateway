# 安全边界

## 凭据与密钥

- 设备 operational private key 只能在设备本地生成和使用；App、Gateway、日志、测试 fixture
  和 Git 均不得接触真实私钥。
- Gateway 只接收 CSR、公钥可验证的 installation proof 和运行证书材料。不得增加“上传私钥”、
  “Gateway 代签 proof”或 App 代设备确认的捷径。
- `GATEWAY_INTERNAL_TOKENS_JSON` 是受控非生产运行时映射。真实 token 不得写入 `.env.example`、
  镜像、测试 golden、日志或提交记录。
- activation state 文件包含 code hash、CSR、certificate 和 proof nonce，必须按敏感运行状态处理，
  保持父目录 `0700`、文件 `0600`，不得放入仓库或静态资源。
- AWS credential 只通过标准 provider chain 注入；禁止在配置、代码或文档示例中写长期 key。

## 授权与隔离

- App 路由先把 Bearer token 解析为可信 internal user subject；未配置 authenticator 时 fail closed。
- activation 查询对错误 subject 返回 not found，避免确认其他用户的 activation 是否存在。
- 设备目录只列出当前 subject 已完成安装证明的 active identity，并保持最小字段集。
- activation code 是短时、一次性授权能力，不是设备永久身份，也不能扩大为通用 API credential。

## 设备通道限制

QR、AP 和 BLE 只负责把 method-bound payload 交给本地设备。当前受控 demo 没有硬件绑定的
出生身份证明，因此 AP/BLE 不能宣称抵抗同链路主动 MITM，也不能作为 production 安全结论。
installation proof 只能证明 certificate 对应私钥已在设备侧可用，不能反向证明设备来源。

## AWS 边界

- 最小操作限于创建 CSR certificate、创建 Thing、附加 principal/policy、读取 ATS endpoint 和
  在 proof 通过后激活 certificate。
- Thing prefix 和 policy name 必须由运行配置提供并受目标账号约束。
- 普通开发、测试和文档任务不创建、不更新 AWS 资源。真实部署、IAM、资源回收和 smoke test
  必须由独立部署流程处理，并取得明确环境授权。
