# 测试与验证

## 测试归属

| 变更 | 最小测试位置 |
|---|---|
| HMAC v1、canonicalization、时间窗和 nonce | `internal/internalauth/*_test.go`、Redis adapter test |
| activation 状态、过期、幂等、proof、binding | owning module tests + PostgreSQL integration test |
| 路由、internal app 隔离、JSON、状态码和响应脱敏 | `internal/httpapi/*_test.go` |
| AWS 调用顺序、inactive 创建、激活和不完整响应 | `internal/awsiot/provisioner_test.go` |
| env 默认值、internal app、PostgreSQL/Redis URL | `internal/runtime/config_test.go` |

行为变化先写能因目标缺口失败的测试，再实现最小修复。AWS adapter 测试使用 fake client；单元
验证不得依赖真实 AWS credential 或修改远端资源。

## 交付命令

从 `aws-iot-gateway` 根目录执行：

```sh
gofmt -w <本次修改的-go-文件>
go test -race -count=1 ./...
go vet ./...
git diff --check
```

PostgreSQL 行为还要对隔离 test database 设置 `TEST_POSTGRES_URL`；普通 skip 不能作为数据库集成证据。

文档-only 变更至少运行链接/路径核对、敏感占位符扫描和 `git diff --check`。未运行真实 AWS
smoke 时必须明确写“未执行”，不能把 fake 测试描述为已部署或 AWS 资源已验证。

## 完成标准

- 最新命令输出与本次 diff 对应，不复用旧分支证据。
- 测试覆盖正常、无效输入、过期、错误用户、重试和外部失败路径。
- 没有 token、私钥、activation code 或 AWS credential 出现在 diff、日志和测试输出中。
- 跨仓 DP 契约变化已同步 Gateway 正式 DP profile seed、TXW82x 固件/Demo App 入口和相应 contract tests；bootstrap 公共契约按部署文档单独核对。
