# 数据库设计规范

本规则是 `aws-iot-gateway` PostgreSQL schema 的强制规范。它继承固定旧仓
`develop-lzc@a3c5c453313097fe76b8fdcaa39baac3a995552b` 中 ExploreX API 已验证的数据库工程约束，
但只适用于 Internal AWS API 的窄域数据；不得借此恢复 Developer、Project、Product、Factory、
IDevID、RMA、tenant 或平台 OTA 模型。

## 权威源与 migration

- 当前尚未上线或量产，`migrations/sql/001_initial.sql` 是唯一 schema 权威源；它必须直接描述最终窄域
  schema，不保留旧宽泛表名、过渡 `ALTER TABLE` 或历史 migration 债务。
- 正式上线后不得改写已应用 migration；后续从 `002` 开始使用连续的
  `NNN_<name>.up.sql` / `NNN_<name>.down.sql`，每个新 `.up.sql` 必须有同名 `.down.sql`。
- 应用 runner 自动执行 `001_initial.sql` 与后续 `.up.sql`，必须跳过 `.down.sql`；回滚只能针对明确环境由
  操作者按倒序受控执行，不能在服务启动时自动降级。
- migration、repository SQL、schema contract test、真实 PostgreSQL integration test 和本快照必须原子更新。

## 命名

- 表名使用精确的复数名词；设备权威表是 `device_registry`，关系/能力表使用
  `device_bindings`、`device_commands`、`device_recordings` 等完整语义，禁止 `devices`、`bindings`
  这类宽泛名称。
- FK 列名必须自解释：目标语义前缀 + `_id`，如 `device_registry_id`、`device_binding_id`、
  `device_activation_id`、`webhook_outbox_id`。
- 主键默认 `id uuid`。自然键或复合主键必须在 `migrations/README.md` 登记业务理由；当前
  `device_schedules.device_registry_id` 是“一设备仅一份已确认投影”的明确例外。
- 普通索引命名 `idx_<table>_<purpose>`，唯一索引命名 `uniq_<description>`；PK、FK、UNIQUE、CHECK
  约束名必须包含当前表与列语义，表/列 rename 后不得遗留旧名。

## 结构与删除语义

- 可变业务表包含 `created_at`、`updated_at`，并用统一 `set_updated_at()` trigger 维护；调用方可显式
  写时间用于审计事实，但普通 UPDATE 不得绕过 trigger。
- append-only event、delivery attempt、idempotency 和 audit 表可只有 `created_at`/业务发生时间；例外
  必须在 schema 快照说明。
- 状态使用小写 `TEXT/VARCHAR + CHECK`，不用 PostgreSQL ENUM，不用无语义整数或布尔代替状态机。
- 核心设备、activation、binding 关联默认 `ON DELETE RESTRICT/NO ACTION`；真正从属且无独立审计价值
  的 session/delivery 才能 `CASCADE`。审计引用需要保留时使用 `SET NULL` 或不建 FK，并记录原因。
- PostgreSQL 是业务权威；不得把 binding/token/activation 状态转存 Redis 或本地 JSON。

## 数据库硬约束

- 优先使用 PK、UNIQUE、CHECK、FK 和 partial unique index 表达不变量；这些不足时才使用 PL/pgSQL trigger。
- trigger 函数命名 `enforce_<table>_<invariant>()`，trigger 命名 `trg_<function>`；必须同时有
  `COMMENT ON FUNCTION` 与 `COMMENT ON TRIGGER`。
- 业务拒绝使用稳定 PostgreSQL code。binding 用户不可变使用 `23514 check_violation`，错误 message
  保留稳定短语 `is immutable once set`。
- `device_bindings.binding_external_user_id` 一旦插入不可修改为另一个用户；同值幂等更新允许。
  设备移交必须先走显式 unbind/recommission 生命周期，不能 UPDATE 覆盖主人。
- 全局同一设备只允许一个 active binding，使用 partial unique index；不得把多个 internal app 解释成 tenant。

## 测试门禁

- 上线前的静态 contract test 必须验证目录只有 `001_initial.sql`，并验证窄域表集合、FK/索引/trigger
  命名和平台域没有回流；新增 `002` 后再启用 up/down 配对门禁。
- 真实 PostgreSQL integration test 使用独立临时 schema，验证 init 可从空库建立、约束错误码、trigger
  合法/非法路径和 runner 幂等；新增后续 migration 时再补对应正向与受控 down 回滚测试。
- 未设置 `TEST_POSTGRES_URL` 时可以跳过本地集成测试，但该 skip 不能作为 merge/release 证据。
- 测试数据库必须与 `explorex_api` 隔离；不得 drop/clean 开发者已有的 `public` schema。
