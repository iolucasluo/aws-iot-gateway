# Internal AWS Gateway 业务流程图

> **代码反向工程文档。** 本目录描述当前 `aws-iot-gateway` 已实现的窄域 Internal AWS API，以及已发布
> `Gateway Device Bootstrap Contract` 的硬件接入边界；不是未来平台设计稿。
>
> 最后按代码、发布器和消费者核对：2026-08-18。

## 范围

Gateway 的完整闭环是：内部 App backend 代表已登录用户创建 activation → 设备首次安装运行身份时登记
`device_registry` → AWS IoT Thing/证书准备与确认 → 原子创建全局 binding → 设备运行期的受控操作、事件与媒体。

在 activation 之前，无可信墙上时钟的设备还必须先完成一次窄域的 signed time bootstrap。这个启动前
信任输入不是任意板子各自维护的环境配置：Gateway 只发布一份完整的公开 Contract，Taixin、Anyka 和后续
硬件分别以自己的 build adapter 校验并嵌入。该供应链流程见首篇文档；它不改变下列业务生命周期的 owner。

它有意不包含 Developer 登录、Project、Product 管理、Factory、IDevID、RMA、平台 OTA 或 tenant。Gateway
只保留 `products` 作为由显式 seed/受控运维维护的最小只读激活目录；App 读取 active PID 后必须显式提交，
不存在默认 PID。
`/api/v1/openapi/*` 仅为 LivPet 的 wire compatibility 名称，不表示存在旧 IoT 平台 OpenAPI 身份体系。

## 阅读边界

- 本目录描述 Gateway 看到的请求、持久化和 AWS 边界；手机 UI、QR/AP/BLE 的交互与设备私钥/证书文件
  安装由 `aws-iot-demo-app`、`anyka-av-workspace` 拥有。
- Bootstrap Contract 是启动前的公开信任输入，不是 Gateway runtime `.env`、commissioning payload、App HMAC
  配置或设备凭据。设备还没有可信时间时，只允许调用精确的 HTTP time-bootstrap 窄路由；随后才可严格 TLS
  连接 Gateway 并进入本目录其余 activation/binding 流程。
- “local Gateway”描述部署位置；共享硬件 Contract 的规范环境名是 `development`，目录为
  `deploy/device-bootstrap/contracts/development/`。当前此目录尚未发布；不得用个人 DHCP 地址或私钥伪造它。
- 设备端 QR/AP/BLE 当前是受控开发/演示配网通道。没有已实现且验证过的出生身份时，不能把本文当作
  抗主动 MITM 或量产安全证明。
- `binding_external_user_id` 是 Internal App backend 从其登录会话派生并 HMAC 签名的归属字段。
  Gateway 比较其精确值，但不拥有终端用户登录系统，不能自行证明某个客户端任意声称的“同一人”。
- 图中“数据库事务”只表示 PostgreSQL 原子性；AWS IoT API 调用不参与该事务。文档会明确标出两者边界。

## 维护规则

- 代码、migration 和测试是事实源；流程图不得从旧 IoT 平台需求文档复制 Project、IDevID 或 Factory
  语义。
- 改动 HTTP 路由、activation 状态、表/FK、Token 授权、MQTT topic、ACK 语义或 AWS 生命周期时，必须
  同步更新对应单篇流程文档及本索引。
- 改动 Contract schema、发布器、环境目录、CA/keyring、轮换规则或任一硬件消费者映射时，必须同步更新
  Bootstrap Contract 接入流程、[格式契约](../contracts/device-service-bootstrap-v1.md)和
  [部署者手册](../../deploy/device-bootstrap/README.md)；不能只改某块板的本地配置。
- 每篇必须独立可读：列出参与方、关键实现位置、Mermaid 图、成功路径、失败/安全边界和验证证据。
- 未跑过的 staging、真机或生产能力必须标成未验证，不能由单元测试或流程图推断为已交付。
